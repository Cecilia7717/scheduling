from pathlib import Path

md = r"""# Alibaba Cluster Trace Experiments

This directory contains the real-data experiments for evaluating the scheduling
algorithms on workloads derived from the Alibaba cluster trace.

The main goal of this experiment is to compare:

- **MaxFlow + Passes**
- **Min-Cost Flow**

on natural Alibaba DAG workloads and study how their running times scale with
the size of the resulting scheduling instances.

The experiments use a fixed target utilization of

\[
U = 0.70.
\]

Each Alibaba job is treated as one independent scheduling workload.

---

## 1. Dataset

The experiments use the Alibaba cluster trace stored under:

```text
data/
```

The main trace files used by the preprocessing pipeline are the batch-task and
batch-instance data.

To avoid repeatedly scanning the full instance trace, instances are
preprocessed into per-job files:

```text
data/instances_by_job/
    j_1.csv
    j_2.csv
    ...
```

These files are generated by:

```text
split_instances_by_job.py
```

---

## 2. Alibaba Job Statistics

`all_job_stats.csv` contains lightweight statistics for Alibaba jobs,
including:

- number of DAG tasks,
- total number of instances,
- observed time horizon,
- number of valid task rows,
- number of invalid task rows.

These statistics are used as a cheap first-stage filter before loading the
more expensive per-instance data.

`analyze_alibaba_jobs.py` contains utilities for analyzing these job
statistics and the distribution of Alibaba workload sizes.

---

## 3. Converting Alibaba Jobs to Scheduling Instances

Each Alibaba job is converted into one single-machine scheduling instance.

For each DAG task \(i\), the raw release time and deadline are derived from its
usable instances:

\[
r_i = \min_k s_{ik},
\]

\[
d_i = \max_k e_{ik}.
\]

The CPU-weighted work of the task is

\[
w_i = \sum_k (e_{ik}-s_{ik})c_{ik},
\]

where \(c_{ik}\) is the average CPU usage of instance \(k\).

### Processing-Time Scaling

Processing times are scaled so that the total processing demand corresponds to
a fixed utilization \(U\):

\[
p_i = \alpha w_i,
\]

where

\[
\alpha = \frac{UH}{\sum_i w_i},
\]

and \(H\) is the observed horizon of the Alibaba job.

The current experiments use:

```text
U = 0.70
```

### Precedence-Aware Effective Windows

The DAG precedence constraints are used to tighten task windows.

Effective releases are propagated forward:

\[
R_i =
\max\left(
r_i,
\max_{j\in pred(i)}(R_j+p_j)
\right).
\]

Effective deadlines are propagated backward:

\[
D_i =
\min\left(
d_i,
\min_{j\in succ(i)}(D_j-p_j)
\right).
\]

The resulting scheduling job is therefore

\[
J_i=(R_i,D_i,p_i).
\]

---

## 4. Energy Intervals

Each workload horizon is divided into six equal-duration energy periods:

```text
Green | Brown | Red | Green | Brown | Red
```

with costs:

```text
Green = 0
Brown = 1
Red   = 2
```

The capacity of each interval equals its duration.

---

## 5. Workload Validation

An Alibaba job is included only if:

1. its task names expose a reconstructable DAG;
2. the DAG is valid and acyclic;
3. every task has at least one usable instance;
4. the observed horizon is at least 6 time units;
5. effective release/deadline windows are valid;
6. every task fits within its effective window; and
7. MaxFlow + Passes finds a feasible schedule.

Some Alibaba task names are opaque identifiers such as:

```text
task_LTQzNDAxMzg3NzYwNDk5MzI1ODE=
```

These jobs are excluded because the predecessor relationships cannot be
reconstructed from the task names.

This is particularly common among the largest Alibaba jobs and therefore
limits the maximum DAG size available for the real-data experiment.

---

## 6. Building the Scaling Dataset

The main dataset builder is:

```text
build_alibaba_scaling_jobs.py
```

Run it with:

```bash
python3 build_alibaba_scaling_jobs.py \
    --output alibaba_scaling_jobs_all \
    --utilization 0.70
```

The builder searches Alibaba jobs by DAG-size range, performs the complete
validation described above, and materializes the selected feasible workloads.

For densely populated DAG-size ranges, representative feasible workloads can
be sampled. Sparse larger ranges can be searched exhaustively. The final
runtime plots use each workload's actual DAG task count rather than the
sampling-band label.

The output directory has the form:

```text
alibaba_scaling_jobs_all/
    j_xxx/
        tasks.csv
        instances/
            <task>.csv
        energy.csv
        selection_info.csv

    summary.csv
    feasible_candidate_pool.csv
    rejected_candidates.csv
    band_summary.csv
```

### Output Files

`summary.csv`
: Workloads selected for the final experiment.

`feasible_candidate_pool.csv`
: All feasible candidates discovered during dataset construction.

`rejected_candidates.csv`
: Rejected workloads and the corresponding rejection reason.

`band_summary.csv`
: Number of candidates tested, feasible workloads found, and workloads selected
for each DAG-size range.

---

## 7. Scheduling Algorithms

The scheduling implementations are contained in:

```text
maxflow.py
```

### MaxFlow + Passes

The algorithm constructs a flow network and performs three passes:

1. Green energy
2. Green + Brown energy
3. Green + Brown + Red energy

Flow from earlier passes is retained when later energy levels are enabled.

### Min-Cost Flow

The comparison algorithm constructs the corresponding min-cost flow problem
using energy costs:

```text
Green = 0
Brown = 1
Red   = 2
```

Both algorithms solve the same scheduling workloads.

---

## 8. Running the Scaling Experiment

The main experiment runner is:

```text
run_alibaba_scaling_experiment.py
```

Example:

```bash
python3 run_alibaba_scaling_experiment.py \
    --root alibaba_scaling_jobs_all \
    --utilization 0.70 \
    --repeats 5
```

Each solver is executed repeatedly and median running time is used as the
primary runtime measurement.

Results are written under:

```text
alibaba_scaling_jobs_all/runtime_results/
```

including:

```text
runtime_summary.csv
runtime_repetitions.csv
```

`runtime_summary.csv` contains workload characteristics and aggregate timing
statistics.

`runtime_repetitions.csv` contains the individual timing measurements from
each repetition.

---

## 9. Measuring Instance Size

The experiment uses two main workload-size measures.

### Number of DAG Tasks

```text
num_tasks
```

This measures the size of the original Alibaba DAG.

### Number of Job-Interval Edges

```text
num_job_interval_edges
```

This measures the size of the main job-to-interval portion of the flow network.

The latter is particularly important because two Alibaba jobs with similar
numbers of DAG tasks can produce very different flow-network sizes depending
on their release/deadline windows.

The experiment therefore reports runtime against both DAG size and
job-interval edge count.

---

## 10. Plotting Results

Figures are generated using:

```text
plot_alibaba_scaling.py
```

Run:

```bash
python3 plot_alibaba_scaling.py
```

The main figures compare median runtime of MaxFlow + Passes and Min-Cost Flow
against:

1. number of DAG tasks; and
2. number of job-interval edges.

Runtime is shown on a logarithmic scale.

Each point represents a distinct natural Alibaba workload.

The job-interval-edge plot is the primary algorithmic scalability figure,
because it more directly captures the size of the flow network solved by the
two algorithms.
